Your stacks, covered.

Back up the config that makes your containers yours.

Docker stacks

Schedules follow each stack’s timezone. All schedules start paused.

Include stacks in manual backup below. Selected stacks run one at a time, stopping and restarting their running containers.

i
A smaller, restorable backup

Compose files and your selected config or volumes are archived together. Containers are stopped for a consistent copy, then restarted before upload. Images and unselected media mounts stay out.

BRING YOUR CONFIG BACK

Restore a backup

Choose a container on the selected Docker host and upload its backup to restore your files.

Use a Cloud Backup ZIP with its manifest and data, a ZIP containing one downloaded backup, or an existing .tar.gz backup.

Running containers stop during restore and restart afterward. Backed-up files overwrite current files; files absent from the backup are kept. Compose files and images are kept as they are.

View restore in Activity →

Google Drive

Mirror each new archive off-site.

Connect or reconnect Google Drive

On a LAN IP, run rclone authorize "drive" on your own computer, complete Google sign-in, then paste the token JSON below. Your Google password is never entered here.

Using a custom rclone client? Set the matching client ID and secret below before saving the token.

rclone's shared Google client is being retired during 2026. If the default connection fails, use your own Google client with Drive API enabled. Generate the token with rclone authorize "drive" "CLIENT_ID" "CLIENT_SECRET", then enter those same credentials below.

Browser OAuth / custom client

For browser sign-in, register a Google Web OAuth client with Drive API enabled. Use an HTTPS hostname or localhost, and sign in to this app at that hostname first. Google does not accept a private LAN IP as a web redirect.

Your backups may contain secrets

Compose files, .env files and application config can contain credentials. Archives are compressed, not encrypted. Use a private NAS share and Drive folder. Mirroring adds backup files; it never syncs or deletes unrelated files.

ONLY WHAT MATTERS

Image mappings

Tell the app where each image keeps its config and application state.

i

For automatic config backups, unknown images need a mapping. You can also choose volumes or enter config paths on the Stacks page. Paths are inside the container. Review broad folders such as /data to avoid backing up media. Tags are ignored when matching.
